DOCKER HUB DEPLOYMENT - FOUR MODEL VARIANTS

Each Dockerfile downloads and checksum-verifies its model manifest during build.
Images contain ComfyUI, model weights, custom nodes when required and the RunPod
handler. Models live under /comfyui/models; no network volume is needed.
One Docker Hub image and one Queue endpoint per variant. Workflow API is unchanged.

Variant             Model weights    Worker container disk    Builder free disk
Qwen-2.1-Q4         14.63GB          50GB                     100GB
Qwen-2.1-Q8         17.62GB          60GB                     100GB
Minimax-H3-INT8     55.10GB          100GB                    200GB
Minimax-H3-BF16     99.50GB          150GB                    350GB
Disk allowances are planning estimates, separate from GPU VRAM. Actual image
sizes include the base image and dependencies. Build sequentially and reclaim
unused build cache only after confirming it is no longer needed.

BUILD
Use a Docker-enabled linux/amd64 builder with adequate disk and runtime.
Build context is repository root. Substitute your Docker Hub username and tag:
  docker build --platform linux/amd64 -f Qwen-2.1-Q4/Dockerfile -t docker.io/<dockerhub-user>/qwen-2.1-q4:<version> .
  docker push docker.io/<dockerhub-user>/qwen-2.1-q4:<version>
Windows builder helper (requires Docker installed and already signed in):
  .\Build-And-Push.ps1 -DockerHubUsername <dockerhub-user> -Version <version>
Use -Variants to build a subset. The helper stops on a failed build/push.
Repeat with each matching Dockerfile and lowercase image name. Authenticate to
Docker Hub via its standard login flow; never commit tokens or passwords.
Do not use standard small-disk hosted CI for large MiniMax images without first
checking available disk. Earlier RunPod GitHub builds hit size/time limits;
Docker Hub stores completed images but does not build them or remove RunPod limits.
A sufficiently provisioned temporary builder or suitable build service is needed.
Choose repository visibility deliberately; private images need RunPod pull credentials.

RUNPOD
Deploy from a Docker image using an immutable tag or digest. Use the folder name
as endpoint name. Queue; active workers 0; max workers 1 initially; one GPU.
Use memory.txt/GPU-options.txt for GPU planning. No volume attachment and no
volume-specific data-center restriction. Configure private registry credentials
if needed. Leave the image entrypoint/start command unchanged.
Smoke-test build and worker startup, then submit the corresponding client-example
workflow and verify media output. New registry images are not yet built/tested.

COST AND EXISTING STORAGE
Zero active workers permits scaling to zero; startup, inference and idle timeout
are billed. Docker Hub charges/limits depend on provider plan and usage.
The earlier 180GB ComfyUI-Models network volume remains retained and billed.
It is no longer required by these Dockerfiles; deletion requires a user request.
No new endpoints were created during the interrupted GitHub deployment flow.

API
Backend continues sending input.workflow and optional input.images to the
corresponding endpoint. Keep RunPod keys backend-only. Preserve generated media
in app-owned object storage; Docker Hub is for worker images and weights.
